# AGENTS.md

- Bridge connections (and so pi) live here in the service worker, not in the side panel. Closing the panel must not stop pi or lose the conversation.
- pi's session file is the record of the conversation. IndexedDB holds only the chat list; don't store transcripts or events there.
- Settings are owned here (`settings.ts`): this is the only code that writes them, and it answers the side panel's `SettingsRequest`s.
- Post on every port (native and panel) with `postInParts` and read every port through `joinParts` (both in `src/parts.ts`). Chrome caps messages at 1 MB from the bridge and 64 MiB elsewhere; long chats and images go past both.
- Each chat with pi running has its own bridge connection, and a bridge's pi stays on one session for life. Route a bridge's events to the chat that opened it, never to whichever chat is on screen; tell chats apart only by their connection, never by timing or by counting replies.
- Switching chats never stops a run. A chat off screen keeps its bridge while the bridge reports `busy` (only the bridge knows its run, queue, input in flight and compaction), while an idle report predates the latest request sent on that connection (`requests` vs `sent`), or while a message to it is unanswered; once none holds, its bridge stops. Count every request posted to a bridge in `sent`. Text a chat hands back off screen waits in chrome.storage.local (`returnedTo`), not in memory. Never infer idleness from pi's events. Deleting a chat stops its bridge.
- Chat bubbles come only from pi (`user` chunks). Don't echo a sent message: until pi answers (`prompt_result`) it is held in `unanswered` and goes back to the message box if the bridge goes away.
- Requests that change the chat or reach pi (prompt, chat switches, compact, model) run one at a time through `inOrder` in `pi-session.ts`, so a message still being stored can't land in the next chat. Stop, restart and queue edits (steer, edit, remove) skip it: they act on what is on screen now, and the bridge orders them against pi. Nothing queued may wait on pi.
